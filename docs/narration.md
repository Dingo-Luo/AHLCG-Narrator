# 配音脚本、编号与音频映射

## 内容在哪里

- `data/core.json`、`data/dwl.json`、`data/ptc.json`：网页正文的唯一编辑来源，继续保存中文。
- `data/narration/chapters.json`：固定战役与章节编号。
- `data/narration/index.json`：自动生成的编号登记簿。记录每段的中文录音文本、原文位置、是否配音、版本和文本校验值；必须保留并加入版本管理。
- `docs/配音脚本.md`：自动生成的可搜索脚本，包含所有编号及其原文路径。标记「不配音」的条目只供定位。
- `data/narration/audio.json`：已完成录音与段落编号的映射，目前为空。
- `assets/audio/zh-CN/`：实际中文音频。尚未生成或调用语音服务。

修改正文后运行 `npm run build:narration`，不要直接修改生成的脚本或索引。`npm run check:narration` 检查索引是否与正文一致，以及登记的音频是否存在、是否匹配当前文本。

## 编号含义

格式为 `战役-章节-类型-文本块-段落`。例如 `0-1-0-3-1` 表示基础版第1章、故事类型、第3个文本块、第1段。

| 层级 | 固定含义 |
| --- | --- |
| 战役 | 0 基础版；1 敦威治；2 卡尔克萨 |
| 章节 | 0 序章；1–8 正式剧本；101、102 幕间；199 尾声 |
| 类型 | 0 故事；1 结局；2 密谋正面；3 密谋背面；4 推进正面；5 推进背面 |
| 文本块 | 本章节、类型内的永久文本块编号；具体故事分支或卡牌字段见来源信息 |
| 段落 | 一条保存的文本段落，不受屏幕宽度、自动换行影响 |

敦威治开局的两个剧本使用固定的出版顺序编号，不随游玩顺序改变。卡尔克萨同一幕间的新旧版本使用同一章节号、不同文本块，来源键始终区分版本。卡牌版本由卡牌代码区分；正反面由类型区分。

首轮按原文顺序分配编号。后续插入段落只增加新号码，不使之后的段落全部改号；简单文字修改保留原编号并更新校验值。拆分、合并或同时改动多段而无法明确匹配时，会发放新编号，旧编号进入 `retired`，不重复使用。因此编辑后的段落编号可能不再按数字顺序排列，网页和录音稿仍按原文顺序展示。

不要删除编号登记簿、手动重排编号或更改已有章节映射。音频文件名不依赖卡牌中文标题，避免标题修改或同名版本造成混淆。

## 哪些内容配音

故事步骤与结局文本按段编号。卡牌正反面的 `flavor`、`back_flavor` 为叙述文字；`text`、`back_text` 中仅 `<blockquote>` 内的段落允许配音。

卡牌标题、目标、强制效果、费用、条件标题、游戏结算以及未翻译提示均编号定位，但 `speak` 为 `false`。斜体和中文引号本身不表示旁白，例如引号内的毁灭标记规则仍然不配音。引用作品的作者署名保留在网页原文，不进入录音文本。单独的游戏符号转为对应中文读法。

不要把整张卡牌文字直接交给配音服务。仅使用索引中 `speak: true` 的 `text`。网页逐段提供播放入口，防止把同一张卡牌上不同条件的两个故事分支连续读出；未显示的卡背及条件分支不显示其播放入口。

如果未来新增卡牌的叙述不在这些字段或标记内，应先整理正文的叙述标记，再生成索引，不通过猜测句子内容来自动纳入配音。

## 用户示例

「巴黎阴谋(版本一)」是卡牌 `03204`，卡尔克萨第5章、推进卡正面。

- 旁白编号：`2-5-4-2-1`
- 来源键：`card:03204:flavor`
- 正文位置：`data/ptc.json#/cards/03204/flavor`
- 配音文本：你走出火车站，经过圣巴拿波教堂时，耳旁飘来一阵风琴声。这么晚了还在布道吗？这奔放奇特的和音扣紧了你的心弦，你不禁驻足倾听了片刻才继续上路。巴黎很大，而你手头的线索很少……

卡牌标题和后面的两个目标另有定位编号，但不配音。

## 录音如何接入

索引中每条可配音记录包含 `id`、`text`、`textHash` 和建议的 `audioPath`。

建议文件路径：

```text
assets/audio/zh-CN/2/5/2-5-4-2-1.08791eb037b8.mp3
```

文件名是永久编号加上文本校验值的前12位；正文修改后生成不同路径，避免浏览器缓存或误用旧录音。音频的角色、语速和生成模型可在后续制作工具中另存，不能替代编号和文本校验。

录音完成并试听确认后，在 `audio.json` 中登记完整的文本校验值：

```json
{
  "version": 1,
  "clips": {
    "2-5-4-2-1": {
      "src": "assets/audio/zh-CN/2/5/2-5-4-2-1.08791eb037b8.mp3",
      "textHash": "08791eb037b8b1d410e6860318de800b938c210933b4661aa8a4e0c265c16c9d",
      "status": "ready"
    }
  }
}
```

这只是格式示例，当前没有上述音频文件，不要直接复制为已完成录音。相同录音文本可通过映射指向同一个本地文件；不同文字不得共用旧校验值。

网页每页故事或每张卡牌只显示一个“播放配音”按钮，按当前显示顺序连续播放 `speak: true` 的段落；卡牌按钮位于“翻面”左侧。段落编号保留在索引和隐藏定位标记中，不再显示逐段标签或按钮。缺失或无法解码的 MP3 会自动跳过，翻面、换页或再次点击按钮会停止当前队列。

已登记录音仍要求 `status: ready` 且完整 `textHash` 匹配。未登记的段落会尝试当前索引的 `audioPath`，因此可以直接按标准文件名加入 MP3；没有文件时跳过。已明确标记草稿、过期或路径无效的映射不会播放。正文与索引不一致时不会使用旧定位标记或录音。

正文修改后仍可运行构建命令生成新稿；构建输出会列出过期或缺失音频。检查命令会拒绝这些问题，直到相应录音重新制作或从映射中移除。删除映射不会自动删除音频文件。校验值只能核对登记的文本版本，不能自动证明音频实际说出了正确内容，仍需试听。

## 制作顺序

1. 校对中文正文和故事分支，运行 `npm run build:narration`。
2. 在录音稿或索引中按编号定位；仅对 `speak: true` 的 `text` 录音。
3. 按 `audioPath` 保存 MP3，试听后登记到 `audio.json`。
4. 运行 `npm run check:narration`、`npm test`。
5. 网站直接按编号查找并播放，无须为每段音频单独修改页面代码。
